# M1 Codex review — Kimi B web deliverable

**FAIL — real browser life loop exists, but creator retry and resume navigation fail required behavior.** Read B's M1 report and reviewed current server/creator/game code. B began M2 edits in the same UI files during this review; source references below describe the current inspected implementation. This is M1 acceptance only, not review/approval of M2 scaffolding or the next M0 art pass. No implementation edits.

## Blocking findings and concrete guidance

1. **FAIL — uncertain creation retry makes a second life (high).** `web/static/creator.js:259` allocates request_id inside the click handler. On a network/parse failure, catch reenables Start life but throws away that operation ID; another click generates a new ID. In actual Chromium with temporary saves, intercepted the first successful POST response and simulated a network loss *after server commit*. Result: one saved life after the error; clicking Start life again produced **two** lives. Server exactly-once cannot help when client changes the key.

   **Guidance:** persist a pending creation operation containing an immutable profile snapshot and request_id before sending; reuse that exact operation on uncertain retry, including page reload, until a definitive response/reconciliation or deliberate new-life action. If profile edits imply a new life, make that an explicit separate action while preserving recovery of the uncertain one. Add a browser regression that drops a response after commit, retries and restarts/reloads, then asserts one game/one identity. Double-click disabling is insufficient.

2. **FAIL — deep-link parameter overrides Resume selection (medium).** `web/static/game.js:636` reapplies location.search.game on *every* loadGame call. Resume handler at `:86` sets the newly selected game in sessionStorage, then loadGame replaces it with the original query ID. Real browser reproduction: open `/game?game=<A>` → All lives → Resume B; sessionStorage/game view still select A. An invalid deep link similarly remains authoritative after selecting a valid life.

   **Guidance:** consume deep-link selection only at initial navigation or treat the URL as the canonical state and update it via history.replaceState/pushState for Resume/All lives. Never leave stale URL and storage authorities fighting. Test two distinct named lives, invalid link recovery, refresh and a new tab. Preserve per-tab isolation.

3. **NEEDS-FIX — action retries also discard operation identity (medium).** `web/static/game.js:523`, `:533` generate a new request ID each click; catch at `:550` discards the previous operation. attempt has no uncertain-result retry path despite the report's “kept across retries” claim. If an action succeeds but its response is lost, the next click initially uses a new key/stale revision; it refreshes rather than retrieving the stored successful response, leaving the user uncertain whether their intended action ran.

   **Guidance:** use one pending operation object with game_id, original expected_revision, action/payload and request_id, persisted per tab until reconciliation. Offer a retry that resends identical data; server checks replay before stale revision. On definitive validation/conflict rejection clear/reconcile deliberately; on transport failure keep the operation. Avoid automatically issuing a new mutation after refresh. Test dropped responses for Age and a decision in real browser, asserting exact final age/effects and clear UI result.

4. **NEEDS-FIX — person-name portrait coverage/shared component incomplete (medium).** Resume rows at `web/static/game.js:79`, timeline participant names at `:182` and pending participants at `:475` contain names without portraits. Browser probe measured zero SVG portraits in resume rows and timeline, despite structured person references being available for journal. Family rows duplicate rendering instead of consuming shared personChip. M1 spec requires portrait component on person references, not only a player/family image.

   **Guidance:** use the shared portrait/name component for structured participants and current/completed-life summaries. Extend list projection with a minimal player descriptor/appearance or fetch scoped game summary data; don't attempt to parse names from prose. Preserve stable ID lookups for archived people. Test actual name-bearing surfaces and long names; a chip class on a text-only row is not the avatar component.

5. **NEEDS-FIX — pending dialog has no focus lifecycle and can be hidden without a return path (medium).** Current `web/static/game.html` declares an aria-modal dialog, but `openDecisionModal` at `game.js:466` opens it without moving focus or trapping Tab/inerting background; shared Cancel at `:374` closes the pending choice despite the service blocking all other gameplay. No clear “resume decision” control exists; rendering/reload is required to show it again. Earlier M1 version used an inline card; the issue here is the currently served implementation, not a demand to introduce modal complexity.

   **Guidance:** choose an accessible nonmodal decision card or complete modal behavior: focus first enabled choice/title, keep focus within modal, restore focus, prevent background actions, and give required pending decisions an explicit return/reopen path if dismissal is allowed. Test opening, Tab/Shift-Tab, Escape/Cancel, validation error and completion using keyboard, not just button tabIndex presence.

6. **NEEDS-FIX — HTTP validation and GET error boundaries (low/medium).** `web/server.py:273` bounds Content-Length only above, so negative values can cause an EOF-dependent read. Content-Type substring test accepts invalid lookalikes (`:278`). Actions route at `:416` replaces falsy invalid payloads ([], false, 0) with {}, bypassing service shape validation. GET routes at `:357`/`:368` catch only GameError, so unexpected structural backend errors close the response instead of returning the safe structured 500 promised in the spec.

   **Guidance:** parse exact media type with optional charset, require 0<=length<=limit, reject malformed framing before reading, and preserve payload type for authoritative validation (default only missing/null according to contract). Apply one shared safe unexpected-error response boundary to both GET and POST; fix underlying A envelope errors separately. Add malformed-field cases without logging raw internal data to clients.
