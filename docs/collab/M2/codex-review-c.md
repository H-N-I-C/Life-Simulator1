Gross/tax/expenses only exist in prose, while the one net row prevents an audited machine-readable breakdown. `_money` uses built-in round at `:90`, differing from legacy round_stochastic.

   **Fix before wiring:** A+C freeze one posting request shape and a typed integer quote with gross/tax/expenses/net, owner, sampled expense factor and unique event/leg identity. Include owner+occurrence+leg in idempotence keys. Sample once through explicit per-game rng, persist quote, and project previews without sampling. Agree rounding and allocation so integer gross-tax-expenses == net and debt remains an additional distinct posting. Supply a real C-result→A-Ledger integration test for player and child, same-turn repeated actions and retry, checking each actual balance equals ledger sum.
